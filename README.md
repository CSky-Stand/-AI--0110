# 0110 · 客服回复幻觉检测

智能客服「说瞎话」批量检测工具：对 20 条客服自动回复逐条判定是否存在幻觉（编造优惠、错误参数、越界能力等），并用人工标注 `ground_truth.json` 验证检出率。

- 语言：Go 1.24（仅标准库，零第三方依赖）
- 检测方式：规则引擎（默认主干）+ DeepSeek LLM 复核（可选）+ mock 降级
- 输出：控制台表格 + `reports/report.md` + `reports/report.html` + `reports/results.json` + `reports/metrics.json`

## 快速开始

```bash
# 一键检测 + 评估 + 生成全部报告（默认规则模式，离线可跑）
go run ./cmd/detect eval

# 只跑检测
go run ./cmd/detect run

# 测试（单元 + 冒烟）
go test ./...

# 验证 LLM 连通性（读取 .env 中的配置）
go run ./cmd/detect llmcheck
```

## 一、幻觉分类体系

判定总原则：`system_reply` 中的事实性断言与 `knowledge_base` 冲突，**或** `knowledge_base` 为「无 / 未接入接口 / 需人工」时回复仍给出具体事实、查询结果或完成承诺，即判为幻觉。判定单元是「断言」而非整句——这是 h04（电子发票对、纸质发票错）能被正确识别为「政策偏差」的关键。

| # | 类型 | 严重度 | 定义与触发要点 |
|---|---|---|---|
| 1 | 能力越界 | P0 | 声称已执行系统未接入的查询/操作（物流、退款进度、改地址、升级工单、发券） |
| 2 | 安全误导 | P0 | 涉健康安全，与知识库注意事项相悖（孕妇放心使用） |
| 3 | 优惠编造 | P0 | 杜撰不存在的券/折扣/学生优惠 |
| 4 | 政策编造 | P0 | 退货权益类政策与知识库完全相悖 |
| 5 | 政策偏差 | P1 | 发票/发货类政策部分正确、部分错误 |
| 6 | 参数编造 | P1 | 产品规格与知识库不符（蓝牙、材质、保修、NFC、接口） |
| 7 | 信息编造 | P1 | 杜撰实体信息（退货地址、线下门店、品牌关联） |
| 8 | 信息遗漏 | P2 | 关键信息未告知导致建议不准（30% 用户反馈偏大被说成不偏） |

严重度口径：P0 = 涉及资金/健康/合规或用户会据此行动；P1 = 误导购买决策、引发售后纠纷；P2 = 建议质量下降。

## 二、检测方法

混合路线 C：**规则引擎为默认主干 + LLM 复核可选 + 未配置/失败自动降级**。

1. **规则引擎（默认，离线可跑）**：7 大检查器按优先级执行，每条命中都附「回复原文片段 vs 知识库片段」证据。负样本保护：否定句识别（h12「不支持货到付款」）、同义一致识别（h16 色差说明）、动作未完成识别。
2. **LLM 复核（可选）**：仅对低/中置信命中（h04 政策偏差、h08 政策偏差、h20 信息遗漏）交 DeepSeek 复核，强制输出 JSON（`is_hallucination/type/severity/evidence_span/reason`）。高置信命中与规则判负直接采信，保证确定性。
3. **mock 降级**：未配置 key、网络错误、超时或 JSON 解析失败时，自动降级为规则结果（`method=fallback`，即任务允许的 mock 模式）。

运行模式：`--mode rule`（纯规则）、`--mode mock`（走 LLM 接口但返回规则结果）、`--mode llm`（低/中置信命中做真实 LLM 复核）。

- 混淆矩阵：TP=18，FP=0，FN=0，TN=2（严格口径）
- 类型判对率：**100%**（规则模式，8 类与人工标注完全一致）
- 漏检：无；误报：无
- 争议 case：h04（政策偏差）、h20（信息遗漏）单列，详见 `reports/report.md`

> LLM 模式实测（DeepSeek `deepseek-v4-pro`）：18/18 检出、零误报；对 h20 的类型判断存在波动（一次判「信息编造」、一次 fallback），说明「遗漏」类边界 LLM 亦无共识，故报告以确定性更强的规则模式为基准。

## 四、局限性讨论

1. 规则引擎依赖词表与正则，对同义改写、反讽、复杂句式的召回有限。
2. 「信息遗漏」类最难判：当前只覆盖「约 X% 反馈 + 相反结论」形态，更广义的遗漏需语义级比对。
3. 政策编造 / 政策偏差的边界按本数据集归纳（退货权益类=编造，发票/发货类=偏差），未必能推广。
4. LLM 复核有波动与成本，真实调用依赖模型质量与网络。
5. 改进方向：事实三元组抽取、小样本分类器、安全类强制二次确认、把 LLM 复核范围扩展到规则未命中的可疑样本。

## 五、AI 工具使用情况

本项目使用 AI 工具（Claude / Reasonix 编码代理）辅助完成：需求与方案设计、分类体系提炼、规则与测试用例编写、报告与 README 润色；关键逻辑（规则触发条件、两套口径、证据字段）经人工评审与 20 条 golden 样本验证。

```

```
